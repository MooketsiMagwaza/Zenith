# W02 — Remove the stale and unused parts

State: Done on 8 October 2026, on branch `chore/remove-lovable-supabase` (the evidence is below). One check is left for a person: the source of the deployed page.

Paths below are given as they are after W04 renamed the app's folder to `apps/app`.

## Goal

The repository says only what is true. Auth and sync were removed from the app in an earlier commit, but pieces remain. The owner's words: opening Zenith should not immediately show Lovable and Supabase. A first look at the repository, the app's folders, the dependencies and the README should show a Tauri and React project and nothing else.

## Scope

- Delete the "Accounts & cross-device sync" chapter and the matching table-of-contents entry from `apps/app/README.md`, and fix the "no env vars" and storage-key lists so they match the code.
- Delete `apps/app/src/integrations/supabase/` and `apps/app/supabase/`, which no source file imports, and remove `@supabase/supabase-js` and `@lovable.dev/cloud-auth-js` from the dependencies if nothing else uses them.
- Check `apps/app/src/integrations/lovable/` and `.lovable/` the same way, and remove them if unused. (The owner is making a new Lovable link, so the old one no longer matters.)
- Remove `@cloudflare/vite-plugin`, `@tanstack/react-start`, and `@lovable.dev/vite-tanstack-config` if the build does not use them (the Vite config already uses only the router plugin).
- Remove any Lovable text, badge or link from `index.html`, the web manifest, the READMEs and the page footers, and check the deployed page's source too.
- Replace the "Desktop (Electron-ready)" section of `apps/app/README.md` and its table-of-contents entry with a short pointer to the Tauri pop-up in `apps/popup`.
- Note in the commit how much a fresh `npm install` shrinks once the unused packages are gone; with them, resolving the tree from a cold cache took more than twenty minutes on 7 October 2026.

## What was done

- Deleted `apps/app/.lovable/`, `apps/app/supabase/` (a config file and one migration) and `apps/app/src/integrations/` (the Lovable auth wrapper and the generated Supabase clients). No file outside those folders imported them.
- Removed seven packages nothing imported: `@supabase/supabase-js`, `@lovable.dev/cloud-auth-js`, `@lovable.dev/vite-tanstack-config`, `@cloudflare/vite-plugin`, `@tanstack/react-start`, `@hookform/resolvers` and `date-fns`.
- Removed the 44 shadcn components the app never imports (it uses only the dropdown menu), the unused `use-mobile` hook, and the 34 packages only they used (25 Radix primitives, `recharts`, `embla-carousel-react`, `cmdk`, `vaul`, `react-day-picker`, `input-otp`, `react-hook-form`, `react-resizable-panels`, `class-variance-authority`).
- Removed the TanStack Start lint rule and the Vinxi, Nitro and Wrangler ignore entries.
- `apps/app/README.md`: deleted the accounts and sync chapter, replaced the Electron section with a pointer to the Tauri pop-up, added the `zenith.notif.permission` key to the storage table and said which keys bypass the safe wrappers, and made the run, build and Netlify sections use npm and the real `netlify.toml`. `index.html` and the web manifest had no Lovable text.
- `package-lock.json` was regenerated by `npm install` from the existing lockfile, so the versions of the packages that stay did not move.

## Evidence (8 October 2026)

- **Build.** `npm run build` passes. After the first commit the production build was byte-for-byte identical to the build before it (`diff -r` of the two `dist` folders found no difference). After the second, the two JavaScript bundles and `index.html` are identical except for hashed file names, and the CSS fell from 93.3 kB to 50.9 kB because Tailwind no longer generates classes that only the deleted components used; no CSS selector was added.
- **Search.** `grep -riE "lovable|supabase"` over the repository, excluding `node_modules`, finds only this work order. `package-lock.json` has neither, and no `cloudflare`, `react-start`, `workerd` or `wrangler` either.
- **Install size.** `npm ci --dry-run` from the old and the new lockfile: **670 packages before, 495 after** (175 fewer, 26 per cent). The lockfile went from 921 entries to 643. A real fresh `npm install` with a warm cache took 57 s before and 34 s after.
- **Type check.** `tsc --noEmit` in `apps/app` reports one error, in `src/routes/__root.tsx` (the error component's props type), which was there before this change. The build does not run `tsc`; W04 fixes it.
